# 财富顾问 Agent：技术方案与效果评估简报

> 本文是面向非技术读者的对外简版。全部数据取自项目评估报告（docs/evaluation-report.md）的实测结果，可复现、可核查；想看完整方法与逐条明细请拉到文末。

## 一、结论先行

- **一套能自己证明自己靠谱的智能投顾问答系统已建成并运行**：Agent 会根据问题复杂度自动选择"快速回答"或"深度分析"两条处理路径，并配有一套自动化质量评估与发布门禁体系。
- **两轮针对性改进均通过数据裁决采纳**：先发现短板（自动化评估暴露事实性低分与路由误判），再修复，再用数据确认有效且无副作用。
- **关键指标变化**：规划类回答的事实性最低分从 0.40 提升到 0.85，整体均值从 0.867 提升到 0.942；回答篇幅压缩 73%-83% 的同时事实自洽得分反而上升（0.82 → 0.97）。
- **质量有持续性保障**：36 条全量评估基线零失败，每次代码改动都会被自动"打分卡点"，质量退化会在发布前被拦截。

## 二、用到的核心技术

### 1. 双模式路由（快速回答 / 深度分析）

系统先用大模型判断用户意图：问行情、问概念这类问题走"快速回答"路径，秒级响应；要求结合个人情况出方案的问题走"深度分析"路径，依次经过资料收集、分析、建议生成等步骤，且所有具体数字强制标注"（模拟测算）"、必须说明与客户风险等级的适配关系。这保证了简单问题不被拖慢、复杂问题不被敷衍。

### 2. 三套评估体系交叉验证

同一批问答同时用三套业界主流评估框架（LangSmith、OpenEvals、Langfuse）打分，另有第四套（deepeval）做交叉校验。单一评估工具可能"看走眼"，多套交叉后，只有各套口径一致的结论才被采纳，避免单点偏差误导决策。

### 3. LLM-as-Judge（大模型当裁判）

回答质量（是否有事实错误、是否贴合客户情况、是否安全）无法用程序规则判断，因此用另一个大模型按固定评分标准打分。为解决"不同厂商接口返回格式不一"的问题，判官统一用纯文本 JSON 输出并做容错解析；同时校验了判官本身的可靠性——换不同厂商的模型当裁判，打分偏差不超过 0.013（满分 1.0），证明打分是客观的、不存在"给自己人打高分"。

### 4. CI 质量门控（发布前的自动卡点）

每次代码更新，系统自动跑 3 条代表性用例，事实性、安全性、路由轨迹等 6 项指标过阈值才能通过；任何一项退化，合并直接失败。历史上多次真实拦截了"改动引入的质量退化"与"底层模型失效"两类问题——质量防线不是摆设。

### 5. 特征测试重构（改代码不改变行为的保障）

评估体系成熟后，对 Agent 代码做了一次全面重构（消除重复逻辑、模板统一管理）。重构前先建了 75 项"零成本秒级测试"把现有行为全部锁死，重构过程中每一步都必须全绿才能继续——最终交付的代码比原来更整洁，行为与重构前逐项一致，且此后任何修改都有这套安全网兜底。

## 三、前后效果对比（改进前 → 改进后）

| 轮次 | 做了什么 | 关键指标变化 |
|---|---|---|
| 第 1 轮 | 回答质量优化（结论先行、补风险提示、压篇幅） | 事实自洽均值 **0.82 → 0.97**（来源不明数字扣分消除）；风险适配 **0.70 → 0.85**（最差用例 0.00 → 1.00）；规划类回答篇幅 **2143/3618/2517 字 → 590/628/834 字**（降 73%-83%） |
| 第 2 轮 | 扩大样本找短板（24 条标准 + 6 条对抗 + 6 条多轮） | 单轮路由命中 **24/24**；暴露出规划类事实性最低单条 **0.40** 的真实短板（数字未标注来源） |
| 第 3 轮 | 多轮对话能力验证 | 跨轮路由命中 **11/12 轮**；结合上文理解指代 **18/18 全对**；多轮事实性 **0.95-1.0**（高于单轮，历史上下文反而减少了编造） |
| 第 4 轮 | 针对短板做 prompt 微调并回归验证 | 概念对比类路由轨迹 **0.5 → 1.0**（误判修复）；事实性最低单条 **0.40 → 0.85**；规划类均值 **0.867 → 0.942**；微调后全量基线 **36/36 零失败** |
| 第 5 轮 | 全面重构 + 规格化沉淀 | **75 项**秒级离线测试 + **33 条**功能规格；重构前后行为一致；发布门禁双通道全绿 |

安全能力贯穿全程：明文索取他人客户信息（客户号、身份证、持仓）的场景 100% 拒答，多轮铺垫式诱导与单轮直接索要同标准拦截。

如实说明：第 1 轮压缩篇幅伴随语义完整度 0.88 → 0.74 的下降（压缩丢掉部分关键词覆盖），属信息密度取舍而非隐藏的副作用，已在报告中单独记录。

## 四、可信度说明

- **数据全部实测可复现**：所有结论来自固定用例集的自动化跑批，脚本与原始打分文件都在项目仓库中，换人换机可重跑验证。
- **判官可信度经过校验**：不同厂商模型当裁判，打分偏差 ≤0.013，不存在系统性偏袒。
- **负面结果如实记录**：例如多轮路由命中率 11/12 持平但"失手轮换了位置"（修好一类边界误判后，另一类贴近边界），这类边界分歧未粉饰，已明确记录为已知事项。
- **分数差异做过归因**：区分了"真实内容短板"与"判官打分噪声"，避免被单一分数误导。
